# tooltip 文案规范

> **写解释文案的规则。** 照着这个写，新手才看得懂。

---

## 核心原则

### 1. 写「功能」，不写「原理」

| ✅ 对 | ❌ 错 |
|---|---|
| 「调大 → 关节变慢、更稳」 | 「基于粘性阻尼系数的力矩-速度关系」|
| 「快，但可能穿透」 | 「积分步长与显式欧拉法的数值稳定性相关」|

**理由**：用户要的是「我拧了这个旋钮会怎样」，不是「这个旋钮背后的数学」。

### 2. 每条必须回答三个问题

```
① 这是什么？           → what
② 调大/调小会怎样？    → effects
③ 什么时候该动它？     → when
```

**缺任何一条，这条解释就不合格。**

### 3. 用「→」表达因果

```
调大 → 更「粘」，脚不容易滑
调小 → 更「滑」，像踩冰
```

**比「摩擦系数越大，切向力上限越高」好懂得多。**

### 4. 给经验值

```
经验值：机器人仿真常用 0.001~0.005 秒
```

**新手最缺的就是「该设多少」。**

### 5. 用 ⭐ 标记「新手最该知道的」

```
when="⭐ 新手最该开的开关之一 —— 一眼看懂每个关节的自由度。"
```

**一条文案里最多一个 ⭐。**

---

## 数据结构

```python
@dataclass
class Tip:
    zh: str                       # 中文名
    en: str                       # 英文原名（与 MuJoCo 官方一致）
    what: str                     # 一句话
    effects: list[str]            # 调整效果（2-4 条）
    when: str                     # 什么时候用
```

**键名约定**：用 **MuJoCo 官方字段名**（如 `timestep`、`mjVIS_JOINT`），
便于和上游对齐、便于查证。

## 分类组织

| 表 | 内容 | 对应源码 |
|---|---|---|
| `VIS_FLAGS` | 可视化开关 | `mjVIS_*` |
| `REND_FLAGS` | 渲染选项 | `mjRND_*` |
| `PHYSICS` | 物理参数 | `mjOption` 字段 |
| `SIM_CONTROL` | 仿真控制 | Studio 按钮 |
| `GROUPS` | 显示分组 | `geomgroup` 等 |
| `CAMERA` | 相机 | `MjvCamera` 字段 |

---

## 输出格式

`tip_text(key)` 生成 ImGui 用的换行文本：

```
仿真步长  (Timestep)
────────────────────────────
每次物理计算往前推进多少秒。

调整效果：
  · 调小 → 更精确、更稳定，但一步算得慢
  · 调大 → 快，但可能「穿透」「抖动」「爆炸」
  · 经验值：机器人仿真常用 0.001~0.005 秒

💡 ⭐ 看到关节抽搐、物体穿透时，先调小它试试。
```

- 第一行：`中文名  (English)`
- 分隔线：28 个 `─`
- 空行后：`调整效果：` + 缩进列表
- 最后：`💡` + when

## 一个额外的可能性

MuJoCo 支持在模型 XML 里写自定义文本：

```xml
<custom>
  <text name="提示_髋关节" data="髋关节：控制大腿前后摆动，单位是弧度。"/>
</custom>
```

**实测可解析、可往返。**

**⇒ 将来可以让文案与模型同源**，UI 层按 `<text name="提示_<参数>">` 查表。
好处：**文档和模型一起版本控制，不用维护两处。**
